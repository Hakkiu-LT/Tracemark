## 2026-06-25 - IDOR in Infringement Endpoints Due to RLS Bypass
**Vulnerability:** The FastAPI backend uses `get_supabase()` which uses the Supabase Service Role Key, effectively bypassing all Row Level Security (RLS) rules in the database. Endpoints in `infringements.py` (like `get_infringement`, `get_evidence`, and `update_infringement_status`) were missing manual authorization checks, allowing any authenticated user to access or modify any infringement record via an Insecure Direct Object Reference (IDOR).
**Learning:** Because the Service Role Key is used globally, **every single endpoint** that fetches or modifies user-specific data must manually verify data ownership (e.g., checking `organization_id` or `user_id`). The assumption that RLS will protect data is completely invalid in this backend architecture.
**Prevention:** Always implement and call a manual access verification helper (like `_verify_infringement_access`) before accessing or mutating data on behalf of a user. Look for other endpoints across the API that might be missing these crucial manual checks.
