## 2024-05-18 - IDOR in Infringements Endpoints due to Service Role Bypass
**Vulnerability:** IDOR (Insecure Direct Object Reference) vulnerabilities were present in multiple `/infringements` endpoints (`get_infringement`, `get_evidence`, `update_infringement_status`), allowing any authenticated user to read or modify infringements belonging to other organizations by simply knowing the infringement ID.
**Learning:** The FastAPI backend globally initializes the Supabase client with the Service Role Key (`SUPABASE_SERVICE_ROLE_KEY`) via `get_supabase()`. This completely bypasses Supabase's Row Level Security (RLS) policies. As a result, the database engine does not enforce tenant isolation.
**Prevention:** Manual authorization checks are absolutely mandatory in all API route handlers, especially for endpoints fetching or modifying resources by ID. Route handlers must inject `profile: CurrentProfile = Depends(get_current_profile)` to access the user's natively resolved identity (like `organization_id` or `id`) and explicitly verify resource ownership before permitting access or modifications.
